# BEV research reproducibility tools

The audit CLI checks archived haulage, thermal-model and forecasting results and
plots saved outputs without rerunning HAULSIM or fitting estimators. The separate
[Experiment A trainer](experiments/A) implements the full forecasting workflow
and produces a fresh model refit. Neither workflow establishes field validation.

Use Python 3.12 or later in a virtual environment. From this directory:

```text
python -m pip install -e .
bev-reproduce --help
bev-reproduce hashes --output results/hash-check
bev-reproduce all --output results/reproduction-001
```

Each output path must be new. With no `--output`, the CLI chooses a timestamped
directory under `results/`. The default input root is `data/workspace/`.
An explicit input location can be supplied with `--data-root PATH`.

## Commands

| Command | Operation |
| --- | --- |
| `hashes` | Check the size and SHA-256 of files listed in `data/SOURCE_MANIFEST.json`. |
| `physics` | Reconstruct event energy, reserve accounting and the reference-cell thermal calculation; recompute laboratory residuals. |
| `ml` | Audit saved forecast predictions and associated source records. This command does not fit models. |
| `plots` | Generate supporting plots from saved results. |
| `all` | Run hash verification, physics, ML and plots in that order, in separate output subdirectories. |

The entry point invokes `tools/audit_physics.py`, `tools/audit_ml.py` and
`tools/plot_saved_results.py` using the current Python interpreter and argument
lists. No shell is used. A failed child command stops `all` and returns a nonzero
exit status; previously written output remains available for inspection.

## Input layout

Preserve the original relative directory structure beneath `data/workspace/`:

```text
data/
  SOURCE_MANIFEST.json
  workspace/
    New_Afton_Experiments_2026-10-20/
    APCOM_Coupled_Thermal_2026-10-16/
    APCOM_Study_2026-10-22/
    APCOM_Draft_Experiments_2026-10-27/
  tum/
tools/
  audit_physics.py
  PORTABLE_INPUTS.json
  audit_ml.py
  plot_saved_results.py
```

The physics input manifest lists 24 required files with relative paths, sizes and
hashes. It is kept next to the physics tool. The release-wide source manifest
uses paths relative to `data/`, such as `workspace/...` and `tum/...`. It can be
either a JSON array of file records or an object containing a `files` array.
Each record has `path`, `sha256` and `bytes` fields.

When `--data-root` is supplied, hash verification reads `SOURCE_MANIFEST.json`
from its parent directory. The CLI rejects output inside that input directory
tree. Inputs are read only; SQLite archives are opened in read-only mode by the
physics audit.

Additional raw TUM CSV files are preserved separately under `data/tum/`. They
were **not used by the current forecasting benchmark**. These commands do not
train on them or use them as independent validation of the current forecasts.

## What reproduction establishes

Agreement demonstrates that the stored sources, calculations and saved scores
can be reconciled. The temperature target is generated by an assumed
reference-cell model, rather than measured Z50 pack temperature. The mapping
`I_eq = 2.5 Ah * P_kW / E_nom_kWh` is an equal-power/nominal-energy assumption.
Its units are amperes; that does not identify actual pack or per-cell current.
See [MODEL_AND_LIMITS.md](docs/MODEL_AND_LIMITS.md) for the model boundaries.

The original Experiment A archive retained predictions and fitting records,
but no serialized estimators. The fresh [Experiment A reproduction](experiments/A)
now includes the full training implementation, byte-identical metric tables and
72 newly fitted models dated 28October2026. These are new reproduction artifacts,
not recovered original weights. [Experiment B](experiments/B) separately contains
three older laboratory-model artifacts. Follow each experiment's own README.

HAULSIM is not needed to inspect the archives or run these audits and plots.
Rerunning the native HAULSIM simulations requires the licensed application.
